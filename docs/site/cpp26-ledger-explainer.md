# The C++26 ledger, explained

MOG is C++26-first with a C++23 consumer fallback. This page explains why
that split exists, which features are actually load-bearing, and how the
portability story stays honest instead of aspirational.

## The rule

Every standard-library or language feature the code relies on must be
**probed at configure time and recorded in a committed compatibility
matrix** (`docs/COMPATIBILITY.md`, regenerated by `mog-probe`). A feature is
either:

1. **Expected** on supported toolchains (floor), or
2. **Vendored as a fallback** under `include/mog/polyfill/` with identical
   semantics, or
3. **Absent from the design** - the feature never becomes load-bearing.

Nothing is used "because it should be there by now".

## The current ledger

| Feature | Kind | Status on floor toolchains (GCC 13/14+, per matrix) | Fallback |
|---|---|---|---|
| `std::expected` | library | present since GCC 12 - floor | none needed |
| `std::add_sat/mul_sat/sub_sat` (P0543) | library | **absent** in current libstdc++ | `polyfill/Saturating.hpp` (builtins) |
| `#embed` (P1967) | language | present in GCC 15 / Clang 19; probed | build falls back to file I/O (`MOG_HAS_EMBED`) |
| Pack indexing (P2662) | language | GCC 14+ - floor | n/a (used where floor supports it) |
| `std::inplace_vector` (P0843) | library | absent today | alias to vendored implementation |
| `std::hive` (P0447) | library | absent everywhere usable | not used; arena/generational slots instead |
| `std::function_ref` (P0792) | library | absent | `polyfill/FunctionRef.hpp` |
| Atomic max/min fetch | library | absent as std API | `atomics::fetch_max/fetch_min` CAS loops |

The probe distinguishes *compiler* capability from *stdlib* capability:
`__cpp_lib_*` macros are checked with the exact headers that will compile
the code, in the exact dialect (`-std=c++23` vs `-std=c++26`) of the target
profile. A stale generated header cannot mask a regression - CI rebuilds it.

## Why profiles exist

- **`frontier`/`lab`**: C++26 only, `-march=native` (or `MOG_ARCH=` for
  reproducible codegen), contracts enforced, `-Werror`. This is where the
  engine is developed and measured.
- **`portable`**: baseline ISA (no `-march`), contracts compiled out,
  dialect 26 **or 23** for stock distro toolchains. This is what wheels and
  downstream embedders get: doctrine says an external user reproduces
  experiments on whatever their distro ships.

## Contracts

`MOG_PRE/MOG_POST/MOG_CONTRACT_ASSERT` route through
`mog::contracts::{enforce,observe,ignore}`. Frontier/lab default enforce
(violations abort loudly); portable defaults ignore so shipped artifacts pay
nothing. The mode is runtime-switchable for harnesses that want observation
with context instead of death.

## For contributors

If you reach for a new standard facility:

1. Check `docs/COMPATIBILITY.md`: is it on the floor?
2. If no - polyfill it (semantics-identical, tested) or don't use it.
3. Re-run `mog-probe` and commit the refreshed matrix in the same change.
4. Never gate correctness on a feature the C++23 fallback path lacks;
   the wheel builds run that path in CI on purpose.
